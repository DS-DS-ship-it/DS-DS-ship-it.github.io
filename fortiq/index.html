How it works

1. Signed transactions

Fortiq transactions are created and signed by a client, then submitted to a live AXIOM-powered node. The node validates the transaction, checks nonce and balance rules, and places valid transactions into the mempool.

2. Propose, vote, commit

On the live devnet, validators connect as authenticated peers, propose blocks, exchange votes, and commit new blocks when the required voting threshold is reached. That gives the network a shared canonical tip.

3. State and explorer updates

When a block commits, AXIOM applies deterministic state changes, updates balances and nonces, persists the result, and exposes live network data through explorer-style endpoints for status, peers, blocks, and accounts.

Why Fortiq

Clear public branding

Fortiq gives the network a strong public-facing identity while AXIOM remains the technical core. That separation helps distinguish the market brand from the protocol implementation underneath it.

Fortress + intelligence

The Fortiq name is meant to communicate security, structure, and smart execution. It fits the project’s visual language and makes the network easier to present, market, and remember than a purely technical protocol label alone.
